# Health Data Hub Privacy Policy

Last updated: May 29, 2026

Health Data Hub is a local-first personal health analytics application. It is designed to help a single user review patterns in their own past sleep and mood data. It is not a hosted service, not a medical device, and not a substitute for professional medical advice.

This policy explains what data Health Data Hub is designed to process, where that data is stored, which third-party services are involved, and what choices the user controls.

## Scope

This policy applies to the Health Data Hub application and its local automation in this repository. Health Data Hub v1 is a Sleep + Mood Retrospective Explainer. It uses Oura sleep data, a user-entered mood log, and optional 8 Sleep data only if the 8 Sleep ingestion path is stable.

The application is currently built for local personal use. It does not provide a hosted account system, a cloud dashboard, multi-tenant infrastructure, advertising, data resale, or third-party analytics tracking.

## Data We Process

Health Data Hub may process the following categories of data when the user configures the relevant feature:

- Oura data: sleep summaries and related daily data needed for the retrospective sleep and mood explainer.
- Mood data: user-entered daily mood ratings and optional context labels such as sick, travel, alcohol, unusually stressful, unusual workout, or late meal.
- Optional 8 Sleep data: sleep-related data from 8 Sleep only if that integration is explicitly enabled and passes the project's stability tripwire.
- Derived data: local feature rows, model-ready day counts, model outputs, confidence messages, and retrospective explanation artifacts.
- Local operational data: logs, verification reports, failure records, and sanitized evidence generated by the local build and verification system.
- Credentials and tokens: Oura access tokens and any optional provider credentials supplied by the user for local ingestion.

Health Data Hub v1 intentionally does not collect Garmin, Withings, chest strap, nutrition, medical-record, multi-user, payment, advertising, or location-tracking data.

## How Data Is Used

Health Data Hub uses the data above to:

- import the user's own sleep data from configured providers;
- record the user's own daily mood label;
- build local daily feature rows;
- train and evaluate a local retrospective model only when the model has enough complete data;
- show retrospective explanations using cautious language such as "patterns associated with this rating" and "correlation, not proven causation";
- verify that the local build and ingestion pipeline is working without committing raw health data or secrets to the repository.

Health Data Hub v1 does not use the data to provide medical advice, diagnose conditions, predict tomorrow's mood, generate prospective recommendations, sell data, target advertising, or build profiles for third parties.

## Where Data Is Stored

Health Data Hub is designed to store personal data locally on the user's machine:

- local warehouse data is stored under `data/`;
- sensitive evidence is stored under `private/evidence/`;
- provider credentials and tokens must be stored only in local environment variables, local secret stores, or ignored local files;
- sanitized review or verification evidence may be stored under `docs/evidence/` only after secrets and raw provider payloads have been removed.

The repository is configured so `data/`, `private/`, `.env` files, DuckDB databases, SQLite databases, Parquet files, raw provider payloads, tokens, snapshots, and quarantine payloads are not tracked by git.

The application does not operate a hosted Health Data Hub backend. If the user chooses to back up local files through iCloud Drive, Time Machine, or another backup provider, that backup provider's own terms and privacy practices apply.

## Third-Party Services

Health Data Hub may interact with the following third-party services when configured by the user:

- Oura: used to retrieve the user's Oura data through the Oura API. Oura remains responsible for Oura accounts, Oura devices, Oura's cloud service, and Oura's own privacy practices.
- 8 Sleep: optional and only used if the 8 Sleep ingestion path is explicitly enabled. 8 Sleep remains responsible for its own account, device, cloud service, and privacy practices.
- GitHub: used to host this source repository and project documentation.
- Local AI/build tools: the repository includes an autonomous build system. Project rules prohibit committing or logging raw health data, provider payloads, provider tokens, `.env` files, databases, snapshots, quarantine payloads, or secrets. Raw personal health data should not be sent to coding agents or external AI tools.

Oura API access may require an active Oura account, API application, user authorization, and applicable Oura membership or service eligibility. The user is responsible for complying with Oura's terms and the Oura API Agreement when using Oura API data.

## Sharing and Disclosure

Health Data Hub is designed not to share personal health data with the project maintainer, other users, advertisers, data brokers, or analytics providers.

Data may leave the user's machine only when:

- the user explicitly sends a request to a configured provider API, such as Oura;
- the user chooses to back up local files using a third-party backup service;
- the user manually shares files, screenshots, logs, or repository content;
- the user configures optional third-party integrations in the future.

Sanitized project evidence may be committed only when it does not contain raw health data, raw provider payloads, tokens, secrets, or sensitive local files.

## Retention and Deletion

Because Health Data Hub is local-first, the user controls retention of local data. Data remains on the user's machine until the user deletes it.

To delete local Health Data Hub data, remove the local `data/` directory, `private/evidence/` directory, and any local token or credential files used with the application. To stop Oura API access, revoke the relevant Oura token or application authorization in the Oura account or developer portal.

Deleting local Health Data Hub files does not delete data from Oura, 8 Sleep, iCloud, GitHub, Time Machine, or any other third-party service. The user must use those services' own deletion controls for data held by those services.

## Security

Health Data Hub uses a local-first design to reduce exposure of sensitive health data. The project also enforces repository-level safeguards that reject tracked raw health data, provider payloads, tokens, DuckDB files, SQLite files, Parquet files, snapshots, and quarantine payloads.

No software can guarantee perfect security. The user is responsible for protecting their local machine, operating-system account, disk encryption, backups, provider accounts, API tokens, and any network exposure they configure.

## User Choices

The user controls whether to:

- create or revoke provider API tokens;
- enable or disable optional provider integrations;
- enter mood ratings;
- delete local data;
- run local backups;
- share repository artifacts or screenshots;
- publish or keep private the repository and legal documents.

For Oura, the application should request only the minimum scopes needed for the configured use. For Health Data Hub v1's S03 Oura smoke test, the intended Oura scope is Daily, because the local collector only needs sleep-related data for the user's own retrospective explainer.

## Children's Data

Health Data Hub is not designed for children and should not be used to collect or analyze children's health data.

## Changes to This Policy

This policy may be updated as Health Data Hub changes. Material changes should be committed to the repository with a new "Last updated" date.
